# Independent-key KV 分解与基准

KV 的 get/put/CAS 每次只触碰一个独立键。因此可以逐键检查，而不用搜索大量无关键操作之间的排列。分解依据线性一致性的局部性：各独立键分别满足约定，整体才可能通过。

实现保留了单体检查器作为对照：

```sh
npm run benchmark:partition
node cli.mjs check your-kv-history.json --json
node cli.mjs check your-kv-history.json --json --no-partition
```

两种模式使用同一顺序模型、实时约束和节点预算，区别仅在是否投影为独立键。基准不做缩减，避免把缩减开销混入搜索优化的比较。

## 本地测量样本

环境为 Windows x64、Node.js v24.18.0、Moon 0.1.20261012；预热一次，五次运行取中位数，每次总节点上限 100,000。包含 JSON 解析、检查和结果序列化，不包含进程启动、文件或界面开销。

| 场景 | 两种模式的结果 | 单体节点 → 分解节点 | 单体中位数 → 分解中位数 |
|---|---|---|---|
| 3 键，9 次操作，末键读取不可能值 | violation / violation | 313 → 11 | 1.480 → 0.357 ms |
| 5 键，15 次操作，末键读取不可能值 | violation / violation | 12,717 → 17 | 21.122 → 0.254 ms |
| 20 键，60 次操作，合法历史 | linearizable / linearizable | 60 → 60 | 2.364 → 1.371 ms |

原始测量保存在 [partition-benchmark.json](partition-benchmark.json)。

节点数量由固定输入决定，耗时是一次本机样本，其他机器和输入不保证同样收益。合法样例也显示：分解不一定减少搜索节点；单键历史不会分解。对高度争用的同一个键，仍可能发生组合爆炸。

## 正确性与资源边界

所有分区共享一个预算。只有全部分区通过且合并出了完整全局顺序，才返回通过。合并同时保留逐键见证顺序和原记录中的跨键实时边。某键确定违规可以证明整体违规；资源不足则返回未判定。某个分区失败时，全局回放前缀留空；可以查看缩减记录排查。

原记录在分解前统一校验，所以重复 ID、跨键同一 client 的重叠调用会在拆分前被拒绝。分解只对本项目的独立键 KV 模型启用，不用于多键事务或任意自定义模型。验证与见证合并仍有 O(n²) 开销；节点预算不是时间截止线。

除 1,500 组独立全排列对照之外，还使用 400 组 KV 历史对照分解与单体结果。通过的历史逐一检查完整顺序、全部实时边和状态回放；边界测试验证多个键不能各自获得完整预算。这些测试覆盖了上述输入范围；外部检查器差分验证尚未完成。
